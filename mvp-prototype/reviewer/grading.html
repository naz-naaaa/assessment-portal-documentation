Describe a threat model for a new internal admin tool you'd build. What would you prioritize and why?

I'd start by identifying the trust boundaries — who can reach the tool (internal network only vs. exposed), and what data it touches. Given it's an admin tool, I'd prioritize authentication (SSO + RBAC) and audit logging first, since a compromised admin session is the highest-impact scenario. I'd also threat-model the data at rest — if it stores PII, encryption and access scoping matter more than, say, rate limiting on a low-traffic internal tool.
